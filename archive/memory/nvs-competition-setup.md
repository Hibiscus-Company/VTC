- Camera model: SIMPLE_RADIAL, single camera, f≈925.68, cx/cy exactly centered, k≈0.0079 (~5px corner shift). Stock 3DGS loader was patched to accept it (ignoring k) and to skip images.bin entries with missing files (images.bin has 388 poses = 200 train + 50 test + 138 dropped).
- test_poses.csv convention VERIFIED: rows are byte-identical to COLMAP images.bin entries → standard world-to-camera (qvec, tvec), R=qvec2rotmat(q).T, T=tvec, FoV from fx/width fy/height.
- Score = 0.4*(1-LPIPS) + 0.3*SSIM + 0.3*clamp(PSNR/psnr_max,0,1); psnr_max value not disclosed.
- **Submission format (user-confirmed 2026-07-12): ONLY private_set1 scenes (8), ONLY images listed in each scene's test/test_poses.csv, .JPG, ≤350MB total.** Public scenes are NOT submitted (local validation only). Keep full renders in output/. **Encoding measured on public proxy (q100=706MB doesn't fit): q95ss0 −0.26 pts (!), q96ss0 −0.14, q98+chroma-4:2:0+optimize −0.05 ← USE q98ss2** (3 largest scenes at q97ss2 to fit → 344MB). Chroma subsampling ≈ free here; JPEG q-level is what LPIPS-vgg punishes. Always A/B encode settings via score_submission on public before packaging.

TWO root patterns: (A) test poses densely INTERPOLATED → model already matches native GT → anything that smooths/resamples/regularizes AWAY from direct photometric fit hurts LPIPS; (B) FastGS already does aggressive floater-removal → the whole floater-removal family (opacity-sparsity, likely sky-mask/dome too) is redundant/counterproductive.
